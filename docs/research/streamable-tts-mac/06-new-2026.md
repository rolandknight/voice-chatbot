# 06 — Discovery sweep: open-weight TTS released or majorly updated Feb–Aug 2026

Scope: models the other clusters will not know about because they post-date training data.
Bar (from the brief): Chatterbox Flash on this Mac — ~0.9 s first audio (whole-utterance MLX),
RTF ~0.28; must beat that on Apple-Silicon TTFA while matching Chatterbox clone quality.
All numbers below are quoted from pages fetched on 2026-08-24; "not published" means it was
not on any page I saw.

Headline: the one genuinely new model that meets all three criteria (open weights, streaming,
zero-shot cloning) AND has a Mac port that streams is **dots.tts (rednote-hilab)**, via the
third-party `mlx-speech` runtime — but no Mac TTFA number has been published anywhere I could
find. Voxtral TTS streams on MLX but the MLX port cannot clone (open issue since April) and is
CC BY-NC. MOSS-TTS-Nano streams and clones on CPU/MLX but is 100M params with no published SIM.
Everything else new is CUDA-only or non-streaming.

---

### dots.tts (rednote-hilab / RedNote hilab, released 2026-06-09; MeanFlow + edit variants 2026-08)
- **What it is:** Fully continuous end-to-end AR TTS: frozen 48 kHz AudioVAE latent → Qwen2.5-1.5B-Base LLM backbone → flow-matching acoustic head (no discrete tokens anywhere); ~2B total, native 48 kHz.
- **Weights/license:** https://huggingface.co/rednote-hilab/dots.tts-soar (aligned/default), `dots.tts-base`, `dots.tts-mf` (MeanFlow-distilled, 4/2/1-step). Apache-2.0 code + weights → commercial OK.
- **Size/memory:** 2B params. CUDA peak: 7.86 GB (SOAR, cloning, <10.24 s audio), 5.74 GB (MF). Mac int4 (sb1992 port): ~2.4 GB resident weights, ~6 GB peak for short clips, up to ~13 GB for ~30 s clips (README, Aug 2026).
- **Voice cloning:** Zero-shot from reference audio + transcript (Swift port also does transcript-free timbre cloning via CAM++ x-vector). Seed-TTS-eval on model card: **dots.tts-soar avg WER 2.95 / avg SIM 79.2**; base 2.92 / 78.8; per-language (search summary of card): EN WER 1.30 SIM 77.1, ZH CER 0.94 SIM 81.0. Card says SOAR is the "highest speaker similarity" checkpoint. 24 languages benchmarked (MiniMax Multilingual); weaker WER on Arabic/Hindi/Turkish/Vietnamese. No arena rank published. Fine-tune path: `dots.tts-base` is explicitly "pretrained for fine-tuning".
- **Streaming:** Native. `generate_stream()` yields audio chunks; README: first-chunk latency **225 ms (voice cloning) / 69 ms (text-only)** for SOAR, **204 / 68 ms** for MeanFlow; RTF 0.20/0.18 (SOAR) and 0.15/0.13 (MF). Hardware for those numbers not stated in the README section fetched (an "optimized inference path"; a vllm-omni port request exists, issue #4218). Third-party summaries quote "54 ms first-token" — not on any primary page I saw, treat as unverified. Swift port describes the official streaming as "1T1A interleaved".
- **Mac path:** Three ports plus GGUF:
  - `sb1992/dots-tts-mlx` (pure MLX, Python; weights `shraey/dots-tts-mlx`, int4 ≈2.4 GB vs 9 GB): cloning yes, **streaming NO** (whole clip); no RTF/TTFA published; MF "~2× faster per clip"; tf32-rounding means output is not sample-aligned with PyTorch.
  - `sammcj/mlx-swift-dots-tts` (Swift, fused attention + meanflow): cloning yes, **streaming NO** ("Streaming (1T1A interleaved) … absent from this port"); AR backbone ~3.8× faster than PyTorch-MPS at int4, DiT ~2–2.8× faster, on an M5 Max; fp32 core 8.2 GB → ~2–3 GB quantized.
  - `appautomaton/mlx-speech` (pure MLX, 200 commits): dots.tts SOAR and MeanFlow are the **only models it streams** ("bounded waveform streaming", `--stream`); cloning yes; **no RTF/TTFA numbers published**.
  - mlx-community uploads `dots-tts-mlx{,-int4,-int8,-mf-int4,-mf-int8}` (2026-07-16/17, single-digit downloads). `audio.cpp` 0.6.1 (2026-08-18) has DotTTS Edit/MF/SOAR GGUF with a Metal backend and a "streaming server/session path" for models that support it — not verified for DotTTS specifically.
- **Controls/capabilities:** speed/duration and emotion controls not documented on the card; `dots.tts.edit` (Aug 2026) does speech editing; speech-only (no singing/SFX); 24 languages (107 claimed by blogs — not on the card).
- **Verdict vs the bar:** On paper the best new clone-quality candidate (SIM 79.2 avg on Seed-TTS-eval is above the 0.70–0.73 range of Confucius4/MOSS and Audio8's 63) with a CUDA first-chunk of ~0.2 s when cloning. On the Mac the only streaming path is `mlx-speech` and nobody has published its TTFA; the two better-optimized ports do not stream, so today it can only be assumed to match, not beat, ~0.9 s until someone measures it. Biggest caveat: 48 kHz continuous-latent decode is heavy (13 GB peak for 30 s on int4) and every Mac port is a one-person project.
- **Sources:**
  - rednote-hilab/dots.tts-soar model card — https://huggingface.co/rednote-hilab/dots.tts-soar
  - dots.tts GitHub README — https://github.com/rednote-hilab/dots.tts
  - sb1992/dots-tts-mlx — https://github.com/sb1992/dots-tts-mlx
  - sammcj/mlx-swift-dots-tts — https://github.com/sammcj/mlx-swift-dots-tts
  - appautomaton/mlx-speech — https://github.com/appautomaton/mlx-speech
  - vllm-omni new-model issue #4218 — https://github.com/vllm-project/vllm-omni/issues/4218

### Voxtral TTS / Voxtral-4B-TTS-2603 (Mistral AI, released 2026-03-26; HF updated 2026-03-31)
- **What it is:** ~4B decoder (fine-tuned from Ministral-3-3B-Base-2512) doing AR semantic-token generation + flow-matching for acoustic tokens, over the from-scratch "Voxtral Codec" (hybrid VQ-FSQ); 24 kHz output.
- **Weights/license:** https://huggingface.co/mistralai/Voxtral-4B-TTS-2603 — **CC BY-NC 4.0** (model and reference voices) → **no commercial use**.
- **Size/memory:** ~4B. MLX quants: `mlx-community/Voxtral-4B-TTS-2603-mlx-4bit` (~2.5 GB per blogs), 6-bit (~3.5 GB), bf16. Fits easily in 36 GB.
- **Voice cloning:** Zero-shot from "as little as 3 seconds" (paper). Human eval: 68.4 % win rate vs ElevenLabs Flash v2.5 for multilingual cloning (naturalness/expressivity). No SIM/WER published on card or abstract. 20 preset voices ship. Qualitative: blogs praise timbre + accent + rhythm capture; no independent blind data.
- **Streaming:** Native (streaming + batch via `vllm-omni >= 0.18`). Card: **70 ms latency at concurrency 1 on one H200**, RTF 0.103; 331 ms @16, 552 ms @32. Granularity not stated on card.
- **Mac path:** mlx-audio (Blaizzy) lists Voxtral with "chunked streaming output" = **streaming YES**, but **voice cloning NO** — only the 20 presets; issue #694 ("expose speaker encoder / add_voice_from_audio", opened 2026-04-30) is open with no maintainer reply. `lucataco/voxtral-cli` (4-bit MLX): ~5.0×/6.2×/8.1× real-time on a "short prompt benchmark" for quality/balanced/fast profiles, chip unspecified, presets only, no streaming. Blogs claim RTF <1 on M4 Max and "1.33× real time" on an unnamed quant — not primary. **No Mac TTFA published.**
- **Controls/capabilities:** 9 languages (EN/FR/ES/DE/IT/PT/NL/AR/HI); WAV/PCM/FLAC/MP3/AAC/Opus outputs; no emotion tags or instruct prompts documented on the card.
- **Verdict vs the bar:** Likely matches or beats Chatterbox on clone naturalness (per Mistral's own eval) and streams on MLX, but on the Mac it cannot clone at all today, and the NC license rules out production use regardless. Biggest caveat: license.
- **Sources:**
  - Model card — https://huggingface.co/mistralai/Voxtral-4B-TTS-2603
  - Paper abstract arXiv:2603.25551 — https://arxiv.org/abs/2603.25551
  - mlx-audio issue #694 — https://github.com/Blaizzy/mlx-audio/issues/694
  - mlx-audio TTS model table — https://blaizzy.github.io/mlx-audio/models/tts/
  - lucataco/voxtral-cli — https://github.com/lucataco/voxtral-cli
  - SiliconANGLE release story — https://siliconangle.com/2026/03/26/mistral-releases-open-weights-speaking-ai-model-voxtral-tts/

### MOSS-TTS family incl. MOSS-TTS-Realtime (OpenMOSS / MOSI.AI, family launched 2026-02-10; v1.5 2026-06-18)
- **What it is:** Discrete-token AR family over MOSS-Audio-Tokenizer (12.5 tok/s): MossTTSDelay 8B (multi-head parallel RVQ, delay pattern), MossTTSLocal (time-synchronous RVQ blocks + depth transformer; card says 1.7B, GitHub says Local-v1.5 is 4B), MossTTSRealtime 1.7B (hierarchical text–audio inputs for realtime), plus Nano 100M (own block below).
- **Weights/license:** https://huggingface.co/OpenMOSS-Team/MOSS-TTS — Apache-2.0 → commercial OK.
- **Size/memory:** 8B / 4B (or 1.7B) / 1.7B / 0.1B. MLX quants exist: `mlx-community/MOSS-TTS-8B-8bit` (2026-03-24), `MOSS-TTS-Local-Transformer-MLX-8bit` (2026-04-11). Mac memory not published.
- **Voice cloning:** Zero-shot from short reference; v1.5 notes "more stable voice cloning" and better long-reference/short-text cases. MossTTSLocal: **EN SIM 73.28 % / WER 1.93 %; ZH SIM 79.62 % / CER 1.44 %** (card). No arena rank.
- **Streaming:** MossTTSRealtime: **TTFB 180 ms (post-warmup, L20 GPU), RTF 0.51**; "LLM-first-sentence + TTS TTFB = 377 ms". MossTTSLocal has a "native streaming design" via SGLang-Omni real-time decode. Delay 8B is non-streaming. Backends: SGLang-Omni (Delay, Local), vLLM-Omni (Delay, Realtime, Nano), llama.cpp (GGUF backbone + ONNX codec).
- **Mac path:** mlx-audio table: MOSS-TTS **cloning YES, streaming NO**. mlx-speech: MOSS Local, streaming no, cloning no. No Mac RTF/TTFA published. MOSS-TTS-Realtime has no MLX upload I could find.
- **Controls/capabilities:** token-level duration control, phoneme-level pronunciation (Pinyin/IPA), `[pause X.Ys]` markers, language tags, voice/character design and multi-speaker dialogue (MOSS-TTSD), sound effects; 31 languages in v1.5.
- **Verdict vs the bar:** Clone quality (SIM 73) is respectable but the streaming variant (Realtime) has no Mac port and the MLX ports of Local/8B are whole-utterance only — so it loses on Mac TTFA. Biggest caveat: streaming exists only on CUDA serving stacks.
- **Sources:**
  - Model card — https://huggingface.co/OpenMOSS-Team/MOSS-TTS
  - GitHub — https://github.com/OpenMOSS/MOSS-TTS
  - mlx-audio TTS table — https://blaizzy.github.io/mlx-audio/models/tts/
  - mlx-speech — https://github.com/appautomaton/mlx-speech

### MOSS-TTS-Nano-100M (OpenMOSS, released 2026-04-10; ONNX 2026-04-17; evals 2026-04-27/29)
- **What it is:** 0.1B pure AR "audio tokenizer + LLM" over MOSS-Audio-Tokenizer-Nano (~20M, RVQ 16 codebooks, 12.5 Hz), **48 kHz stereo** output.
- **Weights/license:** https://huggingface.co/OpenMOSS-Team/MOSS-TTS-Nano-100M — Apache-2.0 → commercial OK.
- **Size/memory:** 100M + 20M codec; memory not published (will be well under 1 GB).
- **Voice cloning:** Zero-shot multilingual cloning with automatic chunking for long input. **No SIM/WER published** on README (an "evaluation updates" changelog entry exists — numbers not in the fetched content).
- **Streaming:** Native streaming with "low realtime latency and fast first audio"; "streaming generation can run on a 4-core CPU"; RTF < 1 on 4 CPU cores per blogs. **No first-audio number published.**
- **Mac path:** ONNX CPU build "runs smoothly on a single CPU core on a MacBook Air M4" (README). "MLX-Audio: recently added support"; `mlx-community/MOSS-TTS-Nano-100M` (2026-04-24, 600 downloads). Whether the MLX path streams is not stated (mlx-audio's table lists "MOSS-TTS" as non-streaming, which may or may not cover Nano). audio.cpp has a MOSS-TTS Nano GGUF.
- **Controls/capabilities:** 20 languages; long-form chunking; no emotion/instruct controls documented.
- **Verdict vs the bar:** Would almost certainly beat 0.9 s TTFA (100M model streaming on CPU) but at 100M params with no published SIM it is very unlikely to match Chatterbox's clone quality — it competes with Pocket TTS, not Chatterbox. Biggest caveat: zero published clone-quality evidence.
- **Sources:**
  - GitHub — https://github.com/OpenMOSS/MOSS-TTS-Nano
  - Model card — https://huggingface.co/OpenMOSS-Team/MOSS-TTS-Nano-100M
  - HackerNoon write-up (secondary) — https://hackernoon.com/moss-tts-nano-100m-brings-multilingual-voice-cloning-to-cpus

### Confucius4-TTS (NetEase Youdao, HF updated ~2026-08-14; paper 2026-08-12)
- **What it is:** Text2Semantic GPT-style LLM + Semantic2Acoustic flow-matching (SSL acoustic features), with an ECAPA-TDNN learnable speaker encoder → transcript-free cloning. Total params not on the card (a third-party X post says 1.3B).
- **Weights/license:** https://huggingface.co/netease-youdao/Confucius4-TTS — Apache-2.0 → commercial OK. (Blogs mention a 54 GB resource package.)
- **Size/memory:** not published; `mlx-community/Confucius4-TTS-mlx-int8` exists (2026-06-20, 92 downloads).
- **Voice cloning:** Zero-shot, **no reference transcript required**, cross-lingual and emotion transfer. Seed-TTS-eval: **EN WER 1.49 / SIM 0.700; ZH CER 0.94 / SIM 0.765**. Paper: cross-lingual avg WER 3.73 % on CV3-Eval.
- **Streaming:** Yes — `model.generate_stream` chunk-by-chunk; **no chunk size or latency published**.
- **Mac path:** Requirements say CUDA 12.6; the mlx-community int8 conversion exists but I found no runtime docs or numbers, and no evidence the MLX path streams. audio.cpp lists a Confucius4-TTS GGUF (Metal backend available, streaming unverified).
- **Controls/capabilities:** 14 languages; emotion transfer from reference; language selection; no tags/instruct documented.
- **Verdict vs the bar:** SIM 0.70 is roughly Chatterbox-class on paper; streaming exists but only documented on CUDA, and the Mac artifacts are conversions without a documented streaming runtime — no evidence it beats 0.9 s on the Mac. Caveat: very new (paper is 12 days old), 54 GB package.
- **Sources:**
  - Model card — https://huggingface.co/netease-youdao/Confucius4-TTS
  - GitHub — https://github.com/netease-youdao/Confucius4-TTS
  - arXiv:2608.11650 — https://arxiv.org/abs/2608.11650
  - mlx-community listing — https://huggingface.co/api/models?author=mlx-community&search=tts

### Audio8 TTS Preview 0.6b / 0.1b (Audio8, published 2026-07-28; HF updated ~2026-08-19)
- **What it is:** DualAR (Fish S2 Pro-style): slow AR predicts one semantic token per frame, fast AR predicts codec codebooks; 601M params excl. codec; **44.1 kHz**.
- **Weights/license:** https://huggingface.co/Audio8/Audio8-TTS-Preview-0.6b (+0.1b, +ONNX-INT4) — Apache-2.0 → commercial OK.
- **Size/memory:** 0.6B; ONNX INT4 CPU path "about 1 GiB" (tested on Apple M2).
- **Voice cloning:** Zero-shot, reference audio + matching transcript required. Seed-TTS-eval: **EN WER 1.506 / SIM 63.2; ZH CER 0.950 / SIM 73.1**. SIM 63 is the lowest of the new models here.
- **Streaming:** Server opt-in (`AUDIO8_TTS_STREAM_ENABLED=1`), 12 codec frames/chunk, 128-frame decoder context; H20 GPU warm p50 0.691 s for ~5.9 s output, RTF 0.116 — **no first-packet number**.
- **Mac path:** ONNX INT4 runs on macOS CPU (M2 tested, ~1 GiB), no PyTorch needed; `mlx-community/Audio8-TTS-Preview-0.6b-bf16` (2026-08-04, 457 downloads) but no mlx-audio model entry found. No Mac RTF/TTFA published.
- **Controls/capabilities:** 11 languages; 1024-token max per generation; no emotion tags documented.
- **Verdict vs the bar:** Loses on clone quality (SIM 63); Mac streaming unmeasured. Interesting only as a small-footprint fallback.
- **Sources:**
  - Model card — https://huggingface.co/Audio8/Audio8-TTS-Preview-0.6b
  - GitHub — https://github.com/Audio8-AI/Audio8_TTS
  - HackerNoon (secondary) — https://hackernoon.com/audio8-tts-preview-06b-compact-multilingual-voice-cloning

### VoXtream2 (herimor / KTH, released 2026-03; paper arXiv:2603.13518)
- **What it is:** 0.5B fully-AR "full-stream" TTS (starts speaking from the first word, streaming text in + audio out), Mimi codec, dynamic speaking-rate control updatable mid-utterance.
- **Weights/license:** https://huggingface.co/herimor/voxtream2 — weights CC-BY-4.0, code MIT/Apache-2.0 → commercial OK with attribution.
- **Size/memory:** 0.5B; 2.2 GB VRAM (4.2 GB with enhancement).
- **Voice cloning:** Zero-shot, 3–10 s prompt (max 20 s); prompt-text masking allows any-language prompts. SIM/WER not on card/README (paper has them; not fetched).
- **Streaming:** **74 ms first-packet / RTF 0.256 uncompiled, 63 ms / 0.173 compiled, on RTX 3090**; 1 min max per session.
- **Mac path:** **None.** Ubuntu 22.04 + CUDA 12 only; no CPU/MPS mention; vllm-omni port requested.
- **Controls:** speaking rate (syllables/s), CFG.
- **Verdict:** Best published GPU TTFA of the sweep but CUDA-only — no Mac path.
- **Sources:** https://github.com/herimor/voxtream · https://huggingface.co/herimor/voxtream2 · https://arxiv.org/abs/2603.13518 · https://github.com/vllm-project/vllm-omni/issues/1962

### FlashTTS (ASLP-lab / NWPU, arXiv 2026-06-08, Interspeech 2026)
- **What it is:** Lagged multi-track decoder-only Transformer (16 layers, 768 hidden; blogs say Qwen2-0.5B init) with Multi-Token Prediction + X-pred mean-flow token-to-mel in 2 NFE + HiFi-GAN, 24 kHz.
- **Weights/license:** https://github.com/ASLP-lab/FlashTTS — Apache-2.0; README says checkpoints released (no direct link seen).
- **Streaming:** Native, streaming text + speech; **first-packet 325 ms** (RTX 4090 cited); 24-token first chunk, then 18-token hop with 6-token lookahead.
- **Voice cloning:** zero-shot; SIM/WER not in abstract/README fetched.
- **Mac path:** **None** (CUDA references only). 6 languages (ZH/EN/FR/DE/JA/KO).
- **Verdict:** CUDA-only research release; no Mac path.
- **Sources:** https://github.com/ASLP-lab/FlashTTS · https://arxiv.org/abs/2606.09141

### MisoTTS / "Miso One" (Miso Labs, released 2026-06-03)
- **What it is:** 8B two-stage: 7.7B backbone predicts first RVQ codebook, 300M depth decoder predicts the rest (32 codebooks) over Kyutai's Mimi tokenizer; English only.
- **Weights/license:** https://huggingface.co/MisoLabs/MisoTTS — "modified MIT" (modification not detailed on the pages fetched).
- **Size/memory:** 8B; 24 GB VRAM recommended bf16, 40 GB+ fp32; CPU "runs but is slow" at 20–40 GB RAM; ~30–40 GB download.
- **Voice cloning:** via optional audio-context input (press: ~10 s clip); no SIM/WER published.
- **Streaming:** README explicitly says the **110 ms** figure is the hosted API's TTFB on H100-class hardware, "not the unoptimized local inference path"; local streaming not documented.
- **Mac path:** none (no MLX/GGUF found); bf16 would fit in 36 GB unified memory but nothing is ported.
- **Verdict:** Not a Mac candidate; included because it is a headline June release. Caveat: local path is unoptimized and streaming undocumented.
- **Sources:** https://github.com/MisoLabsAI/MisoTTS · https://www.misolabs.ai/blog/miso-tts-8b · https://www.marktechpost.com/2026/06/04/miso-labs-releases-misotts-an-8b-emotive-text-to-speech-model-with-open-weights/
