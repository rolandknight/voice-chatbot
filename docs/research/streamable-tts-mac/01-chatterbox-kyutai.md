# Cluster 01 — Resemble AI Chatterbox family & Kyutai TTS family
Research date: 2026-08-24. All numbers below carry the date/source they were read from; "not published" means no page I fetched carried the number.

### Chatterbox Flash (Resemble AI, PyPI 0.1.0 2026-05-28; paper v3 2026-08-21)
- **What it is:** Chatterbox's 0.5B T3 (Llama-520M + one extra `[MASK]` token) fine-tuned from an autoregressive decoder into a *block-diffusion* decoder (parallel masked decoding inside a block, block-by-block streaming) → S3Gen flow-matching vocoder → 24 kHz; GE2E voice encoder for the speaker embedding. Paper: "Prior-Calibrated Block Diffusion for Streaming Zero-Shot TTS" (arXiv 2605.30748; v1 2026-05-29, v3 2026-08-21).
- **Weights/license:** https://huggingface.co/ResembleAI/chatterbox-flash (t3_flash.safetensors, s3gen.safetensors, ve.safetensors, tokenizer.json) — MIT; commercial OK. PerTh watermark applied by default (Resemble blog).
- **Size/memory:** 0.5B T3 + S3Gen + VE. Mac memory not published; your own PoC (MLX fp16) is the only local measurement. HF card: MLX 4-bit option exists for the T3 backbone only ("S3Gen vocoder and voice encoder stay in the specified dtype").
- **Voice cloning:** zero-shot from a reference wav (the family's usual ~10 s prompt; the paper doesn't state a minimum). Seed-TTS test-en (HF card / paper, Aug 2026): **SIM-o 0.704, WER 1.96, UTMOS 4.09** at α=0 (prior-calibrated, no early decoding); **SIM 0.704 / WER 2.04 / UTMOS 4.08** at the default α=0.5; the AR Chatterbox baseline it was fine-tuned from scores **0.685 / 2.20 / 4.10** on the same table; ground-truth SIM 0.734. So Flash *slightly beats* the original 0.5B Chatterbox on SIM and WER on Seed-TTS-eval; no comparison against Turbo is published anywhere. Qualitative consensus: the family clones timbre well, style/delivery mostly comes from the `exaggeration`/temperature knobs (which Flash's CLI doesn't expose). No fine-tune path shipped (repo is "inference-only", 1 commit).
- **Streaming:** *Architecturally* native block-by-block streaming ("emits audio as each block is committed"). Published TTFP (time-to-first-packet) on **NVIDIA H100**, concurrency 1 (paper v3 / HF card): **118 ms, RTF 0.107** at D=16, α=0.5 (default); **106 ms, RTF 0.091** at D=16, α=0.75; **103 ms, RTF 0.076** at D=32, α=0.75. Paper Table 10 notes a "modest quality drop versus offline" when chunk-vocoder + early-emit streaming optimizations are on, and that the model "collapses at substantially larger block sizes (D≥128)". **But the released package exposes no streaming API**: the README documents only `ChatterboxFlashTTS.from_pretrained(...).generate(text, audio_prompt_path=...)`; no `generate_stream`, no FlashInfer streaming entry point; PyPI has a single release (0.1.0, 2026-05-28). The GitHub repo (resemble-ai/chatterbox-flash) has 1 commit and **0 issues**, and the HF discussions tab is empty, so there is no public bug consensus on over-generation; the only documented failure mode is the paper's large-block collapse. (Your PoC's silent-runaway/RNG-drift findings are not corroborated or contradicted by anything public.)
- **Mac path:** official `chatterbox-flash[mlx]` extra, marked **experimental**: LLaMA backbone on Metal via MLX (4-/8-bit quant via `mlx.nn.quantize`, T3 only); S3Gen + voice encoder remain PyTorch (CPU) — exactly what your PoC observed. HF card publishes a Mac number: **"measured on a Mac M4 at the default configuration": RTF 0.778 (MLX fp), 0.665 (MLX 4-bit)** — whole-utterance, no TTFA, chip variant not specified (base M4 presumably; your M4 Max PoC got ~0.28 with tuned knobs). The MLX path does **not** stream. Maintainer: Resemble (single-commit repo; no activity since May 2026). No CoreML/ONNX Flash port found (search hits calling "Chatterbox Flash CoreML" resolve to the ebrinz chatterbox-*turbo*-coreml repo).
- **Controls/capabilities:** CLI knobs `--num_steps` (≤10 denoise steps/block), `--temperature` (position temperature, default T=5 in README; sampling temp 0.2 in paper), `--time_shift_tau` (0.5), `--cfg_scale` (paper w=1.0, PMI-CFG), `--n_cfm_timesteps` (S3Gen CFM steps, default 2), block size D, `--dtype`, `--quantize_bits`. **No `exaggeration`, no paralinguistic tags, English only.** No speed/pitch control, single speaker.
- **Verdict vs the bar:** Clone quality: matches/slightly beats original Chatterbox 0.5B on Seed-TTS SIM (0.704 vs 0.685); vs Turbo unknown (Turbo has no published SIM/WER). Mac TTFA: **loses** — the only Mac path is whole-utterance MLX (HF's own M4 RTF 0.78; your tuned 0.92 s first audio). The 103–118 ms TTFP exists only on H100 in an unreleased streaming loop; the biggest caveat is that S3Gen still runs on CPU torch and nothing streams on Mac.

### Chatterbox Turbo (Resemble AI, released 2025-12-15; HF card last touched 2025-12)
- **What it is:** 350M-param streamlined Chatterbox: T3 LLaMA-style AR text→speech-token decoder + *distilled single-step* speech-token→mel decoder (10 steps → 1) + vocoder, 24 kHz; zero-shot cloning via 5–10 s prompt.
- **Weights/license:** https://huggingface.co/ResembleAI/chatterbox-turbo — MIT, commercial OK; PerTh watermark. Also ResembleAI/chatterbox-turbo-ONNX.
- **Size/memory:** 350M (Resemble); MLX conversions report "0.6–0.7B" total incl. S3Gen/VE. mlx-community/chatterbox-turbo-fp16 is 2.99 GB on disk; claude-mlx-tts reports ~4 GB RAM fp16, ~2 GB 8-bit, ~1 GB 4-bit (Aug 2026 README, no chip stated).
- **Voice cloning:** zero-shot; `prepare_conditionals` requires an audio prompt **> 5 s** (code), card recommends 10 s. **No SIM/WER published.** Resemble's Podonos blind tests (naturalness, not cloning): Turbo preferred **65.3 %** vs ElevenLabs Turbo v2.5 (24.5 %), 49.8 % vs Cartesia Sonic 3 (39.8 %), 59.1 % vs VibeVoice 7B (31.6 %). Artificial Analysis arena (snapshot read 2026-08-24): "Chatterbox" Elo 1020, "Chatterbox HD" 1093, Kokoro 1060 (no separate Turbo entry). Consensus: strong timbre match, delivery driven by tags/exaggeration; cross-language prompts transfer accent.
- **Streaming:** **Official repo has none** — `tts_turbo.py` exposes only `from_pretrained/from_local/prepare_conditionals/generate/norm_loudness`, no `yield`. Resemble markets "streaming-ready… 75 ms latency" (GPU, no hardware stated) for its hosted API only. Third-party: devnen/Chatterbox-TTS-Server v2.0.0 — `/tts` with `stream=true` is **sentence-chunk level** ("model synthesizes a full chunk in one forward pass… chunk-level, not token-level"); `/v1/audio/speech` does **not** stream. davidbrowne17/chatterbox-streaming: token-chunk streaming (`chunk_size` default 50 tokens) for the *original* 0.5B model, TTFA **0.472 s, RTF 0.499 on RTX 4090** (README, no date). Known chunk-join issue: HF discussion #18 (2025-12-27) "clicks and pops at audio chunk boundaries" when decoding 10–100-token batches because the decoder output is context-dependent; no Resemble reply. Silent failure/over-generation issues in the family: resemble-ai/chatterbox #531 (silent 1000/1000-token runaway ~5 % of generations), #97 (gibberish on very short inputs), PR #457 (Turbo hallucinates beyond ~350 chars → sentence chunking), #519 (Multilingual `alignment_stream_analyzer` forces EOS too early, May 2026).
- **Mac path:** (a) **mlx-audio** (Blaizzy) has a dedicated `chatterbox_turbo` model: `generate(stream=True, streaming_interval=2.0)` → `stream_generate(chunk_size = max(10, int(streaming_interval*25)))` i.e. **token-chunk streaming, min 10 speech tokens ≈ 0.4 s of audio**, S3Gen/T3/S3Tokenizer all in MLX (VE via numpy), sentence-regex text chunking, `max_tokens` 800, no paralinguistic-tag handling in code (tags are just text). Models: mlx-community/chatterbox-turbo-fp16/-8bit/-4bit. **No measured Mac TTFA/RTF anywhere** (mlx-audio docs, HF cards, Jimmi42 repo all give none). Open bug #898 (2026-08-21): mlx-audio server `/v1/audio/speech` `stream:true` emits one complete container per chunk → audible silence at seams (tested with chatterbox-turbo-fp16 and pocket-tts). (b) **CoreML/ONNX** (ebrinz/chatterbox-turbo-coreml): T3 prefill CoreML + decode ONNX C API + single conditional decoder; **~1.5 s for a ~20-token phrase on M3 Pro, 43 ms/token; claims MLX 8-bit took ~17 s for the same** (date not stated) — whole-utterance, no streaming. (c) PyTorch MPS via Chatterbox-TTS-Server (sentence-chunk streaming). Maintainers: mlx-audio active (v0.5.0 mid-Aug 2026; note: the release page's year labels looked off by one in my fetch — treat exact dates with caution); ebrinz/Jimmi42 hobby repos.
- **Controls/capabilities:** native paralinguistic tags — Resemble lists `[sigh] [gasp] [cough] [laugh] [whisper] [breath]`, HF card `[cough] [laugh] [chuckle]`, mlx port lists 9: `[laugh] [sigh] [gasp] [groan] [chuckle] [cough] [sniff] [shush] [clear throat]`. Knobs (code defaults): `exaggeration=0.0`, `cfg_weight=0.0`, `temperature=0.8`, `top_p=0.95`, `top_k=1000`, `repetition_penalty=1.2`, `min_p=0`. English only. No speed/pitch, single speaker.
- **Verdict vs the bar:** It *is* the bar for clone quality. On Mac TTFA: mlx-audio's token-chunk streaming for Turbo is the one path in this cluster that could plausibly beat 0.9 s (10-token chunks ≈ 0.4 s audio; TTFA = prompt-conditioning + 10 decode steps + S3Gen on a chunk), but **no published Mac number exists** and the chunk-boundary clicks issue (#18) applies. Biggest caveat: unmeasured, and the mlx port silently drops tags handling and hallucination guards.

### Chatterbox Multilingual V3 (Resemble AI, 2026-06-10)
- **What it is:** 0.5B Llama-backbone AR Chatterbox (t3_mtl23ls_v3 + s3gen_v3) retrained on 36.7k h (was 25.6k h) with a rebalanced multilingual mix; 23 languages + 4 dialect packs + 6 tuned "Language Pack" models (25 "languages" in marketing).
- **Weights/license:** shipped inside https://huggingface.co/ResembleAI/chatterbox (t3_mtl23ls_v3.safetensors 2.14 GB, s3gen_v3.safetensors 1.06 GB) — MIT, commercial OK; NVIDIA NIM available; PerTh watermark default.
- **Size/memory:** 0.5B T3 (+S3Gen); mlx-community/chatterbox-multilingual-v3 is 2.71 GB fp32-ish MLX. Mac RAM not published.
- **Voice cloning:** zero-shot; Resemble claims "improved speaker similarity across languages, fewer hallucination-style failures" vs v2 — **no SIM numbers published**. Published CER per language (Resemble blog): English 0.65 %, Italian/German 0.20 %, pt-BR 0.35 %, Spanish 2.89 %, Korean 70.9 %, Vietnamese 75.2 %. V3 is explicitly "optimized to reduce unwanted continuation, repetition, and off-prompt speech" (hallucination was the main v2 complaint; see #519).
- **Streaming:** none in the official repo; Resemble quotes **TTFB < 300 ms on a single H100, ~5× real-time** for its NIM/hosted path. Sentence-chunk streaming via Chatterbox-TTS-Server (v2 model; V3 not listed there yet).
- **Mac path:** mlx-audio `chatterbox` model (PR #869 merged 2026-08-03/04 "Add Chatterbox Multilingual v3"; mlx-community/chatterbox-multilingual-v3 converted with mlx-audio 0.4.7). **The mlx-audio `chatterbox` class ignores `stream` ("Chatterbox doesn't support streaming"), no text chunking, whole-utterance only.** Knobs exposed: exaggeration 0.1, cfg_weight 0.5, temperature 0.8, repetition_penalty 1.2, min_p 0.05, top_p 1.0, max_new_tokens 1000. No Mac RTF/TTFA published. PyTorch-MPS: a Mac benchmark post (LinkedIn, ~Apr 2026) measured original Chatterbox at **RTF 4.55 on MPS** (slow; whole utterance).
- **Controls/capabilities:** `exaggeration`, `cfg_weight`, `temperature`, `language_id`; no paralinguistic tags (Turbo/Nano only); 23 languages; cross-lingual cloning with accent-transfer caveat.
- **Verdict vs the bar:** Possibly ≥ Turbo on cross-lingual cloning but unproven for English; **loses on Mac TTFA** (MLX path is whole-utterance, 0.5B AR + S3Gen). Caveat: only relevant if you need non-English.

### Chatterbox Nano (Resemble AI, 2026-07-06) — newest 2026 Chatterbox release
- **What it is:** 110M-param Turbo-architecture model (same single-step distilled decoder, same training data as Turbo), CPU-targeted, English only.
- **Weights/license:** https://huggingface.co/ResembleAI/chatterbox-nano — MIT, commercial OK, PerTh watermark.
- **Size/memory:** 110M; RAM not published.
- **Voice cloning:** zero-shot from **5 s** clips (Resemble blog) / 10 s (card); "same expressiveness as Turbo"; **no SIM/WER or listening-test numbers published**. The Murmur comparison (2026-08-12) positions Nano as a "draft voice" below Turbo.
- **Streaming:** none in the official code (whole-file generation). Resemble numbers: **10× real-time on GPU, 3× real-time on 8 CPU threads** (no TTFA).
- **Mac path:** card lists MPS; **no MLX/CoreML/ONNX port found** as of 2026-08-24; no Mac numbers.
- **Controls/capabilities:** all Turbo paralinguistic tags (`[laugh] [sigh] [cough] [chuckle] [gasp]`…), `exaggeration` 0.5, `cfg_weight` 0.5; English only.
- **Verdict vs the bar:** Probably below Turbo on clone quality (110M, no numbers); nothing streams and no Mac port → loses on TTFA today; caveat: worth re-checking if mlx-audio adds it (a 110M Turbo could give sub-300 ms chunks on M4 Max).

### Kyutai TTS 1.6B (Kyutai, released 2025-07-03; no model update since)
- **What it is:** Delayed-Streams-Modeling hierarchical transformer: 1B temporal backbone + 600M depth transformer (≈1.8B total despite the name) predicting Mimi codec tokens (12.5 Hz, 32 codebooks, 24 kHz), text stream leads audio by ~1.28 s (delay 2 frames semantic/acoustic); CFG-distilled (no CFG at inference); speaker via cross-attention on a pre-computed voice embedding.
- **Weights/license:** https://huggingface.co/kyutai/tts-1.6b-en_fr (PyTorch), `-candle`, `-mlx` variants — **CC-BY 4.0** (commercial OK with attribution); code MIT/Apache. Voices: https://huggingface.co/kyutai/tts-voices (not gated; mixed CC0 / CC-BY / **CC-BY-NC for Expresso & EARS**).
- **Size/memory:** ~1.8B params; bf16 ≈ 3.6 GB weights, MLX `--quantize 8/4` available; Mac RAM not published.
- **Voice cloning:** **Not available for your own clip in 2026.** Cloning is embedding-based; the encoder needed to produce embeddings (`_mimi_voice.safetensors`, `tts_make_voice.py`) is **still not released** — kyutai-labs/moshi issue #404 (2026-02-16, open, no maintainer reply) documents 404/401 on every route; kyutai.org/tts says custom voices come only via the (now closed) Unmute voice-donation program. What you *can* use: `kyutai/tts-voices` — 228 donated CC0 voices (June 2025–Feb 2026 project), VCTK, CML-TTS (fr), Expresso/EARS (NC), Alba MacKenna, Voice-Zero LibriVox. Quality (Kyutai launch, 2025-07-03, English/French): **WER 2.82 / 3.29, speaker similarity 77.1 % / 78.7 %** (reported as beating ElevenLabs Multilingual v2 by 15 % WER in French and Dia by 12 % SIM) — measured on *their* pre-embedded voices, not zero-shot. Not on the Artificial Analysis or TTS Arena v2 leaderboards. Reviewer (erogol, 2025-08-02): streaming-quality "as good as offline", but "word-by-word generation… sometimes resulting in linear prosody".
- **Streaming:** the most genuinely streaming design in this cluster — **text-in streaming** (word/line as the LLM emits it) and frame-out (80 ms Mimi frames). Published latency: **220 ms first-audio** (Kyutai launch claim; hardware not stated in the card) and **~350 ms at 32 concurrent streams on one L40S** (aibase report of launch, 2025-07-04); repo issue #138 (Sep 2025) reports a user seeing 900–1200 ms TTFA on the Rust server vs the 350 ms expectation, unresolved. Chunk joins are frame-level (codec streaming) so no seam artifacts by construction.
- **Mac path:** official `moshi-mlx` (PyPI 0.3.0, 2025-08-04 — **no release in a year**) `scripts/tts_mlx.py`, `--quantize 8|4`; Candle/Rust backend also ships (Metal builds exist for Moshi). **Does the MLX path stream?** Yes, but poorly: issue #170 (2026-01-07, **open, no maintainer reply**): "Streaming MLX TTS speaks word by word" — choppy, unnatural pauses on an **M2 Max 32 GB**, non-streaming script fine. **No Mac RTF/TTFA numbers published anywhere I found** (kyutai cards, README, DeepWiki, blogs). DSM repo: 105 commits, recent issues about Italian fine-tune (Mar 2026), voice packs (Feb 2026).
- **Controls/capabilities:** English + French; voices from the repo only; `padding_bonus`/speed is unreliable (issues #141, #150); no emotion tags, no instruct prompts; EARS voices carry emotional variants; multi-speaker only by switching embeddings.
- **Verdict vs the bar:** **Fails the clone requirement outright** (no encoder for your own clip) and Mac streaming is broken/unmeasured, so it loses on both axes despite the excellent CUDA streaming design; biggest caveat: no self-hosted cloning at all.

### Kyutai Pocket TTS (Kyutai, v1.0.0 2026-01-13 → v2.1.0 2026-05-04)
- **What it is:** ~100M-param CPU-first streaming TTS: "FlowLM" transformer (~70M) + MLP consistency/LSD sampler (~10M, 1 decode step) + Mimi decoder (~20M), 80 ms frames, 24 kHz; voice conditioning from an encoded audio prompt; 6 languages (English 2026-01/2026-04 variants; fr/de/es/pt/it as larger `*_24l` 24-layer variants).
- **Weights/license:** https://huggingface.co/kyutai/pocket-tts — weights **CC-BY 4.0**, code MIT. The main repo is **gated with automatic approval** (you must accept terms: no cloning without consent, no deception); the voice-cloning encoder lives only in the gated repo — `kyutai/pocket-tts-without-voice-cloning` is the ungated variant (preset voices only). Commercial OK.
- **Size/memory:** 100M; runs on **2 CPU cores**; int8 dynamic quant (torchao, CPU only, ~30 % faster per v2.0.0 notes). Memory not published (small — sub-1 GB expected, not measured).
- **Voice cloning:** zero-shot from a plain wav/mp3 (FluidAudio port: 1–30 s); `export-voice` caches the prompt state as safetensors. **No SIM/WER, MOS, or arena numbers published** (not on Artificial Analysis or TTS Arena v2). HN launch thread (Jan 2026): "voice cloning worked much better than expected", "comparable realism to Chatterbox at half the speed w/o GPU" vs "Kokoro is better for TTS by far"; text-skipping on long inputs (Kyutai's Václav: expected for tiny models, chunk your text). 2026 issues: **#221 (2026-07-15, open)** — v2.1.0 intermittently inserts/repeats words with exported voice profiles on Apple Silicon (rollback to v1 fixes); v2.1.0 notes "fix voice cloning with quantization". Consensus: clones timbre acceptably for 100M, limited prosody/emotional range.
- **Streaming:** native — `TTSModel.generate_audio_stream(model_state, text, frames_after_eos=None)` yields audio chunks (frame-level, 80 ms Mimi frames; StreamingTransformer w/ KV cache); sentence-based chunking for long text. Published: **"~200 ms to first audio chunk"** and **~6× real-time on a MacBook Air M4 CPU** (README; also 2.3–2.5× on a 4-vCPU x86 VM, 6.28× on a T4). Kyutai explicitly measured no GPU speedup at batch 1 on Apple Silicon.
- **Mac path:** (1) official PyTorch CPU path *is* the Mac path (the 200 ms / 6× numbers are M4 CPU); (2) **mlx-audio `pocket_tts`** (mlx-community/pocket-tts, 0.1B bf16): `generate(stream=True, streaming_interval=2.0)` (chunk = interval × sample_rate; lower it for smaller chunks), `ref_audio` cloning, knobs temp 0.7 / lsd_decode_steps 1 / eos_threshold −4.0, pure MLX — no Mac latency numbers published; hit by server seam bug #898; (3) jishnuvenugopal/pocket-tts-mlx (v0.2.1, 37 stars, cloning via HF auth, notes "startup artifacts" needing warm-up/trim); (4) FluidInference pocket-tts-coreml / FluidAudio Swift (frame-by-frame 80 ms streaming, 1–30 s cloning, **no numbers**); (5) slaughters85j native macOS app (Core ML): "sub-second first-audio, ~3× real-time on Apple Silicon" (2026-05-18). Maintainer: Kyutai, active (issues/PRs through 2026-08-17; #240 torchao slower than torch.ao on ARM64 CPU, open).
- **Controls/capabilities:** language selection, `temp`, `lsd_decode_steps`, `eos_threshold`, `frames_after_eos`; **no speed control, no emotion tags/instruct, no pause insertion** (README "not supported: silence in text for pauses"); 24 preset voices; single speaker per call.
- **Verdict vs the bar:** **Beats the bar on Mac TTFA** (~200 ms first chunk on an M4 Air CPU is the only sub-300 ms Apple-Silicon number in this cluster, and it is a real streaming path) but **loses on clone quality** — a 100M model with no published SIM/WER and open 2026 regressions on Apple Silicon (#221); biggest caveat: prosody/expressiveness and long-text stability well below Chatterbox Turbo.
